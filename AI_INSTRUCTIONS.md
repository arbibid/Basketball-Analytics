# СТРОГИЕ ПРАВИЛА РАЗРАБОТКИ ДЛЯ AI-АССИСТЕНТА (JULES)

Ты — AI-ассистент на проекте алгоритмического беттинга (WNBA Bot). Проект является полностью рабочей, сложной распределенной системой. Твоя задача — улучшать код, НЕ ломая существующую архитектуру.

## ТЕКУЩАЯ АРХИТЕКТУРА ЭКОСИСТЕМЫ
1. **Скраперы (Data Collectors):** Собирают статистику команд, составы, судей (RotoWire, NBA Stats). Пишут данные в SQLite.
2. **Даемоны линий:** `betcity_daemon.py`, `fonbet_daemon.py`, `pari_daemon.py` асинхронно парсят коэффициенты букмекеров и обновляют таблицу `odds_history`.
3. **Ядро математики (Main Predictor):** Расчет ELO, Pace, DvP. Ядро сверяет свою вероятность с линией букмекера. Если находит валуй — пишет сигнал в таблицу `bet_signals`.
4. **Умный Маршрутизатор (Bet Router):** Диспетчер, который забирает сигналы из `bet_signals`. Поддерживает два режима (AUTO / MANUAL). Передает сигнал в API конкретного букмекера.
5. **Боевые API-клиенты (Executors):** У нас есть 3 написанных класса `FonbetAPI`, `BetcityAPI`, `PariAPI`. Они используют Playwright для обхода защиты, авто-логина и извлечения токенов из localStorage, а саму ставку бьют через `requests`.
6. **Telegram Бот:** Управляет тарифами, выдает аналитику, позволяет Админу апрувить заявки Роутера в ручном режиме.

## ПРАВИЛО 1: НЕ ПЕРЕПИСЫВАТЬ АВТОРИЗАЦИЮ API
Классы авторизации через Playwright (`login()`) для букмекеров выстраданы и работают идеально. Никогда не предлагай переписать их на Selenium, обычный requests или "чистый" API, если об этом не просят явно.

## ПРАВИЛО 2: БАЗА ДАННЫХ (SQLite WAL)
- База данных единая: `wnba_bot.db`.
- У нас используется `PRAGMA journal_mode=WAL;` и `timeout=60.0`.
- ВСЕГДА используй методы `DBManager` для доступа. Соединения открываются локально (через `conn = self.db.get_connection()`) и всегда закрываются в блоке `finally: conn.close()`.
- ИСПОЛЬЗУЙ только параметризованные запросы (`?`), чтобы избежать SQL инъекций.

## ПРАВИЛО 3: НИКАКОГО УДАЛЕНИЯ СТАРОГО КОДА БЕЗ РАЗРЕШЕНИЯ
В коде могут быть функции, которые кажутся тебе "статусными" (YooKassa, статистика подписок). Строго запрещено удалять их при рефакторинге. Если нужно обновить функцию, оборачивай изменения в блоки `try-except`. При изменении файла увеличивай `# Version: X.X` в первой строке.
